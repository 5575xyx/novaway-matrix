Use this tool when you need to ask the user questions during execution. This allows you to:
1. Gather user preferences or requirements
2. Clarify ambiguous instructions
3. Get decisions on implementation choices as you work
4. Offer choices to the user about what direction to take.

CRITICAL: Whenever you need an answer from the user, you MUST use this tool instead of outputting a text question and stopping. This includes open-ended clarification questions: pass an empty `options` array so the user can type a free-form answer. For choice questions, provide 2-4 options. The tool renders the interactive response UI.

Timing rules:
- Ask questions before irreversible planning or implementation when a user decision is genuinely required. Ask the smallest coherent set; an active workflow may require one question per call.
- Once a todo list has been created, do NOT ask convenience questions. Ask again only for a genuine blocker, conflict, missing credential, destructive action needing consent, or a decision that changes the acceptance criteria.
- In unattended mode the host skips the interaction and returns control to the model with an explicit instruction to record its assumption.

Usage notes:
- When `custom` is enabled (default), a "Type your own answer" option is added automatically; don't include "Other" or catch-all options
- Answers are returned as arrays of labels; set `multiple: true` to allow selecting more than one
- If you recommend a specific option, make that the first option in the list and add "(Recommended)" at the end of the label
