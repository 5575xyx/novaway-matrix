# 自媒体运营（全平台）

这套流程把一次运营拆成五步：**选题 → 写稿 → 预检 → 发布 → 复盘**。
每一步都能单独用；用户只说"帮我发个小红书"，就跳到最后两步。

## 先确认在哪一步

| 用户想要 | 读哪一节 |
| --- | --- |
| 不知道发什么、追热点、拆对标 | 1. 选题 |
| 有素材，要写标题/正文/标签 | 2. 写稿 |
| 稿子写好了，想发 | 3. 预检 → 4. 发布 |
| 发完了，看数据、总结 | 5. 复盘 |

平台口径：小红书 / 抖音 / 视频号 / 快手 / B站 / 公众号。
闲鱼不是内容平台，不套这套流程。

## 0. 硬规则（每次都适用）

- **发布前一定过预检**（第 3 节），平台的拒稿和限流比多问一句贵得多。
- **不要编造数据**：播放量、粉丝数、涨粉率只能来自页面真实数据；拿不到就说拿不到。
- **不要承诺效果**：不写"保证爆"、"必涨粉"，也不要在文案里写医疗/收益承诺。
- **登录态只在用户本机**：绝不把 cookie、token、页面内容发到第三方服务。
- **频率克制**：同一账号短时间内不要连续发布多条（平台会判定营销号）。

## 1. 选题

三个来源，按用户手里的东西选：

1. **用户自己的账号**（最准）：`webview_status` 确认打开着该账号，`webview_navigate`
   到创作中心/数据页，`webview_script` 读最近作品的数据，找"哪类题材数据最好"。
2. **平台热榜**：用 `browser_*` 或 WebFetch 打开公开热榜页面，读完立即离开，不登录。
   各平台热榜：抖音热点宝 / 小红书创作中心「灵感」 / B站热搜 / 微博热搜 / 知乎热榜。
3. **对标账号**：用户在页面里打开某个爆款或在「运营工作台」里选中该账号后，用
   `webview_snapshot` 读标题和正文，拆它的**结构**（钩子 → 信息密度 → 行动号召），
   不要照抄内容。

输出给用户时永远是「3-5 个选题 + 每个选题的一句话理由（依据哪条数据/热榜）」。

## 2. 写稿：按平台原生写，不要一稿多发

同一件事在各平台是**三种文风**，直接复制同一段文案是限流的主要原因之一。

| 平台 | 标题 | 正文 | 标签 |
| --- | --- | --- | --- |
| 小红书 | ≤ 20 字，前置结论 + 情绪词，可带 emoji | 短句分行，100-600 字，先给价值再讲经历 | 3-6 个，用 `#话题` 形式 |
| 抖音 | ≤ 55 字，钩子在前 3 秒说完 | 口播稿：一句一个信息点，前 3 秒抛冲突 | 3-5 个，跟热点话题 |
| 视频号 | ≤ 30 字，偏克制、可信 | 描述 100-300 字，讲清"看完能得到什么" | 2-4 个 |
| 快手 | ≤ 30 字，口语化、称呼"老铁"不端着 | 短，直接说事 | 2-4 个 |
| B站 | ≤ 80 字，玩梗 + 信息量 | 简介写清分P/章节/引用来源 | 分区标签 + 3-5 个话题 |
| 公众号 | ≤ 64 字，标题决定打开率 | 长文：开头给结论，小标题分段，配图点缀 | 不适用（用合集/话题） |

写稿的三条硬要求：

- **去 AI 味**：删掉"首先/其次/最后"「在这个快节奏的时代」「不仅仅是…更是…」这类模板句；
  每段至少有一处具体细节（数字、地点、时间、品牌、价格）。
- **一篇只讲一件事**：标题里的承诺，正文必须兑现。
- **可核验**：引用数据要说出处；说不出处的数字删掉。

写完先自己念一遍：如果一句话读起来像产品说明书，改写成一个人说话。

## 3. 预检（发布前必须做）

发布中心会自动做**确定性**预检（长度、素材形态、极限词、引流词、功效承诺），
在聊天里直接发时，用下面这份清单自己过一遍：

**必须改（否则大概率发不出去或被判违规）**

- 标题/正文为空；视频给了多个文件；公众号文章没标题。
- 医疗/金融承诺：治愈、根治、包治、无副作用、稳赚、保本、零风险、日入过万。
- 站外引流：微信号、加V、vx、扫码进群、私信领取、扣1、链接在简介。

**建议改（大概率限流）**

- 极限词：最好/最佳/最低价、全国第一、顶级、唯一、国家级、100%有效。
  改法：换成可核验的具体事实（"比同类少 30%"）。
- 超过平台长度：小红书标题 20 字、抖音 55 字、公众号 64 字、B站 80 字。
  超了有的平台直接拒，有的**静默截断**——后者更坑。
- 标签重复、超过 10 个、单个超过 20 字。
- 标题超过 30 字（信息流只露前 20 字，钩子等于白写）。

**别忘了**

- AI 生成内容：抖音 / 小红书 / 视频号要求在发布页打开「AI 生成」标识。
- 转载/引用：注明来源，别去掉原作者水印。
- 广告：商业推广需要在平台报备（抖音/小红书都有「内容合作」标记）。

## 4. 发布：两条路，按场景选

**发布中心（推荐用于批量）**

用户点「发布」按钮走的是桌面端一键发布：一次输入 → 多账号（可跨平台），
串行执行、逐条回进度，结果落盘。它已经处理了公众号建草稿（不会误触群发）、
抖音上传完成判据、小红书发布按钮在 closed shadow root 里需要坐标点击等细节。

**webview_* 工具（用于页面里还要多做几步的情况）**

需要先改封面、选合集、调发布时间时，直接在用户眼前那块页面上操作：

1. `webview_status` — 确认打开的账号对不对、登录还在不在；
2. `webview_navigate` — 到发布页（创作中心 → 发布）；
3. `webview_snapshot` — 拿可交互元素的 ref（会下钻 iframe / shadow root）；
4. `webview_fill` / `webview_click` — 逐项填写；
5. 看不到的按钮（如小红书发布）用 `webview_click_at` 按坐标点；
6. `webview_screenshot` — 发布前截一张给用户确认。

公众号正文在 `iframe#ueditor_0` 里，视频号整页在 wujie 微前端的影子树里，
`webview_*` 已经处理；不要退回 `browser_*`（没有登录态）。

**发布后必须回读**：`webview_snapshot` 或 `webview_script` 确认"已发布/审核中"，
再告诉用户成功。页面没确认到就不要说发好了。

## 5. 复盘：数据只从后台读

原则：**读页面，不猜**。每个平台的创作中心都有数据页，先导航再取数：

| 平台 | 数据页（在已登录页面里打开） |
| --- | --- |
| 抖音 | `creator.douyin.com/creator-micro/data/` |
| 小红书 | `creator.xiaohongshu.com/creator/notemanage` |
| 视频号 | `channels.weixin.qq.com/platform/post/list` |
| 快手 | `cp.kuaishou.com/profile` |
| B站 | `member.bilibili.com/platform/home` |
| 公众号 | `mp.weixin.qq.com` → 内容与互动 → 已发表 |

取数的通用脚本（选不到会返回空，别硬编选择器）：

```js
(() => {
  const rows = Array.from(document.querySelectorAll("tr, [class*='item'], [class*='card']"))
    .slice(0, 30)
    .map((node) => (node.innerText || "").replace(/\s+/g, " ").trim())
    .filter((text) => text.length > 5)
  return { url: location.href, rows }
})()
```

数据页会改版，选择器失效时：`webview_screenshot` 看一眼前端结构，
再 `webview_script` 量新选择器，不要反复盲试。

复盘的结论要落到**下一篇怎么做**：

- 哪类选题的数据显著高于平均 → 记下来，下一轮多做；
- 完播/阅读明显低于同账号平均 → 问题在开头 3 秒或标题，不是内容长度；
- 互动（评论/收藏）高但涨粉低 → 缺"关注理由"，结尾要补一句。

## 输出格式

每次汇报都给用户三段，别写成小作文：

1. **做了什么**（发了什么、发到哪、结果如何，带页面确认的证据）；
2. **数据/依据**（从哪个页面的哪个数来的）；
3. **下一步建议**（1-3 条，能直接执行）。

## 常见失败与处理

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 找不到发布按钮 | 按钮在 closed shadow root | `webview_screenshot` + `webview_click_at` 按坐标点 |
| 填写后提交为空 | 富文本组件只认用户输入 | 用 `webview_script` 的 `execCommand("insertText")`，或改用发布中心 |
| 上传一直不完成 | 大文件 + 弱网 | 等，别急着点发布；先用 `webview_snapshot` 看有没有"上传中/取消上传" |
| 公众号没 token | 页面不在后台域名下 | 先 `webview_navigate` 到 `mp.weixin.qq.com`，让它自己带出 token |
| 发布后页面没变化 | 被风控/需要验证 | 截图给用户，让他手动完成验证，别反复点 |
