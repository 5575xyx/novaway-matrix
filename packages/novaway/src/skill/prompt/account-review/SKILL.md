# 账号复盘

复盘的产出不是一张数据表，而是**下一篇怎么改**。

## 铁律：数据只从页面读

- 用 `webview_*` 在**用户已登录的创作中心**里读真实数据；
- 读不到就说「没有取到」，**不要估算、不要编造**；
- 不要用 `browser_*` 去开创作者后台（没有登录态，只会跳登录页）；
- 数字必须能指出来源页面（哪个平台的哪一页）。

## 流程

1. **确认对象**：哪个账号、哪个平台、看最近多少条（默认 30 天 / 20 条）。
2. **导航取数**：`webview_status` → `webview_navigate` 到数据页 → `webview_script` 读列表。
   各平台地址与脚本见 `references/data-playbook.md`。
3. **算派生指标**：完播率、互动率、涨粉率、单条涨粉（公式见参考文件）。
4. **找异常**：和账号自己的中位数比，而不是和全网比。
5. **给动作**：3 条以内，每条能直接执行。

## 分析框架

只看三组对比，不要什么都算：

| 对比 | 回答的问题 | 结论落到 |
| --- | --- | --- |
| 高 vs 低（同账号） | 哪类题材有效 | 下一轮多做哪类 |
| 本次 vs 上周期 | 是在涨还是在掉 | 是否需要换方向 |
| 播放 vs 互动 | 内容质量还是分发问题 | 改开头 / 改结尾 |

诊断口径：

- **播放低、互动率正常** → 分发/封面标题问题，不是内容问题；
- **播放高、完播低** → 开头 3 秒没接住，或内容与标题不符；
- **互动高、涨粉低** → 缺「关注理由」，结尾要补一句；
- **涨粉正常、播放下滑** → 选题开始重复，需要新角度。

## 输出格式

```
结论：<一句话>
依据：<页面 + 数字，最多 3 条>
动作：
1. <下周做的一件具体的事>
2. …
```

不要输出大段表格给用户自己看；表格只放在「依据」里，且不超过 5 行。

## 不要做

- 不把不同平台的播放量直接相加（口径完全不同）。
- 不用「预计涨粉 X」这类无法验证的预测；要说区间就给依据。
- 不因为一两条数据波动就建议大改方向，至少看 10 条。
