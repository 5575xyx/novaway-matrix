# 选题雷达

给用户「下一批发什么」的答案，而不是一堆热榜链接。

## 先补齐三个前提

问不到就不要猜，先确认（一次问完，别挤牙膏）：

1. **平台 + 赛道**：发在哪个平台、做什么内容（如「小红书 · 露营装备」）。
2. **目标读者**：谁会看（如「周末自驾的上班族」）。
3. **目标动作**：涨粉 / 带货 / 引流到私域 / 品牌曝光。

用户已经说清楚的就跳过。

## 三个数据来源，按可信度排序

### 1. 用户自己的账号（最准，优先）

用户在「运营工作台」选中了账号时：

- `webview_status` 确认页面；
- `webview_navigate` 到创作中心数据页；
- `webview_script` 取最近 20-30 条作品的标题与数据（脚本见下）；
- 找**显著高于中位数**的题材，那是这个账号已经被验证过的方向。

```js
(() => {
  const rows = Array.from(document.querySelectorAll("tr, [class*='item'], [class*='card']"))
    .slice(0, 30)
    .map((node) => (node.innerText || "").replace(/\s+/g, " ").trim())
    .filter((text) => text.length > 8)
  return { url: location.href, rows }
})()
```

没有登录态时不要用 `browser_*` 去碰创作者后台（会跳到登录页），直接告诉用户需要先在工作台打开账号。

### 2. 平台热榜（公开信息）

用 `browser_*`（无头浏览器，不需要登录）或 `fetch` 打开公开热榜，见
`references/hotlists.md`。只读公开页面，不登录、不批量翻页。

### 3. 对标账号（公开内容）

用户在页面里打开了某个爆款 / 对标账号时，用 `webview_snapshot` 读标题与正文；
否则用 `browser_navigate` + `browser_snapshot` 打开公开链接。

拆**结构**而不是抄内容：钩子在前几句、信息密度、给出的具体细节、结尾的行动号召。

## 打分与筛选

每个候选选题按 4 项各 0-2 分，总分 ≥ 5 才推荐：

| 维度 | 2 分 | 1 分 | 0 分 |
| --- | --- | --- | --- |
| 相关性 | 直接命中目标读者痛点 | 沾边 | 与账号无关 |
| 依据 | 有具体数据/热榜位次 | 有间接信号 | 纯猜 |
| 竞争密度 | 同类内容少或有差异化角度 | 一般 | 已经烂大街 |
| 可执行 | 现有素材/能力就能做 | 需要补一点素材 | 需要拍摄/出镜等做不到 |

## 输出格式

固定 5 个选题，每个一张卡：

```
1. 标题方向：<一句话>
   平台/形态：小红书图文 · 6 图
   依据：<热榜第 X 位 / 自家某条作品 3.2 万播放，是同账号中位数 4 倍>
   角度：<和已有内容不同的地方>
   风险：<合规/素材/时效，没有就写"无">
   分数：6/8
```

最后给一句**建议先发哪个**，并说明理由（不要五个并列）。

## 硬规则

- **数据必须有出处**：热榜位次、播放量、点赞数只能来自真实页面；拿不到就写「未取到」，不要估算成精确数字。
- **不编造爆款**：没打开的笔记不要描述它的内容。
- **不做「搬运」**：对标是拆结构，不是洗稿；不要复制对方的句子。
- **时效性**：热榜话题超过 48 小时要说明「热度可能已过」。
- **频率**：同一平台连续抓公开页面不要超过每 30 秒一次。
