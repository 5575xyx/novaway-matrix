# 浏览器验证规则（内置全局规则）

## 用内置浏览器，不要起外部浏览器
页面 / HTML 的验证与截图一律用内置的 `browser_*` 工具。它拉起的是无窗口浏览器：
不弹窗、不抢焦点，截图只包含页面本身。

不要用 shell 启动 Chrome/Edge 的 `--remote-debugging-port`，也不要加载或使用名为
`browser` 的外部技能（那类脚本会弹出可见的 Chrome 窗口盖住 NovaWay，用户没法继续
操作，截图往往也变成整屏）。即使技能列表里出现了 `browser`，验证页面时也不要选它。

## 工具
`browser_navigate / browser_snapshot / browser_screenshot / browser_close` 默认就在工具列表里。
点击、输入、控制台、网络、无障碍树是延迟加载的，需要时一次激活整族：

```
tool_search("select:browser_*")
```

1. `browser_navigate(url)`：打开 http/https，或本地 file:// / 绝对路径
2. `browser_snapshot()`：页面文本 + 可交互元素的 snapshot ref
3. `browser_click(ref)` / `browser_fill(ref, value)` / `browser_press(key, ref?)`
4. `browser_screenshot(fullPage?)`：只截页面视口，自动作为「验证结果」展示
5. `browser_console()` / `browser_network()` / `browser_accessibility()`
6. `browser_close()`：验证结束后释放浏览器

工具列表里可能还残留 `mcp__browser__*`（旧的 Playwright MCP 服务）：验证页面时一律用
上面的内置工具，不要用 MCP 那一套 —— 它打开的页面不会同步到右侧预览，也不和用户在
「设置 → 浏览器控制」里配的能力共享状态。

## 怎么验证（对齐 ZCode 的浏览器验证方法）
- **snapshot 是主要观察手段，截图只在"要看画面"时用**。读结构、找元素、确认状态用
  snapshot；不要在同一轮里既 snapshot 又 screenshot。
- **只在三种情况截图**：要看布局 / 样式 / 渲染效果；用户明确要求截图；目标是 canvas /
  自绘控件、snapshot 看不到。
- **一个验证点最多 1 张截图**。不要每点一次就截一张 —— 截图是给用户看的证据，
  不是操作日志。改前 / 改后各一两张足够。
- **只验证"本次对话涉及的改动"**：用户让你改了哪个页面 / 哪个功能，就验证那一个
  以及它直接影响的路径；不要顺手把整个站点全量回归。
- 交互验证：`snapshot` 拿 ref → `click/fill/press` → 再 `snapshot` 确认状态变化
  （文案、计数、可见性），必要时才补一张截图。

## 截图口径
- 网页 / HTML 验证 → `browser_screenshot`
- 只有验证原生桌面应用（资源管理器、IDE、系统设置等）才用 `computer_screenshot`；
  它截的是整块屏幕，不要拿它截网页

## 约定
- 验证刚生成的 HTML 直接用 file://，不必先起 dev server；要真服务时才起本地端口
- 导航到本地页面会同步到应用右侧「浏览器」标签，用户能直接看到你在验证什么
- 截图文件落在 Worktree 的 `.novaway/browser/evidence/`
