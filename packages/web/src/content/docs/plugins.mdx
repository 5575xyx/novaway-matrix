---
title: Plugins
description: Write your own plugins to extend NovaWay.
---

A plugin is a plain TypeScript or JavaScript module that exports **hooks**. NovaWay calls
those hooks while it runs, and your code can read the conversation, change what is sent to
the model, register tools, and add providers. Everything on this page uses
`@novaway/plugin`.

---

## Quick start

Create `.novaway/plugin/hello.ts` in your project:

```ts title=".novaway/plugin/hello.ts"
import type { Plugin } from "@novaway/plugin"

export default {
  id: "hello",
  server: (async () => ({
    "tool.execute.before": async (input, output) => {
      if (input.tool === "bash") {
        console.log("about to run:", output.args.command)
      }
    },
  })) satisfies Plugin,
}
```

Start NovaWay and every `bash` tool call is logged. Files under `.novaway/plugin/` and
`.novaway/plugins/` are picked up automatically — no config entry needed.

## Where plugins live

| Location                        | Scope            | How it is loaded |
| ------------------------------- | ---------------- | ---------------- |
| `.novaway/plugin/*.ts`          | Project          | Automatically    |
| `.novaway/plugins/*.ts`         | Project          | Automatically    |
| `~/.config/novaway/plugin/*.ts` | Global           | Automatically    |
| `novaway.json` → `plugin` array | Global or project | By spec         |

The `plugin` array accepts npm package names, git specs, and paths:

```json title="novaway.json"
{
  "$schema": "https://novaway.ai/config.json",
  "plugin": [
    "./plugin/release-helper.ts",
    "novaway-plugin-git-hooks",
    "@my-org/novaway-plugin-audit@1.2.0",
    "some-plugin@git+https://gitee.com/my-org/some-plugin.git"
  ]
}
```

**npm plugins** are installed with Bun at startup and cached in
`~/.cache/novaway/node_modules/`. **Local plugins** are imported directly; to use external
packages from one, add a `package.json` to your config directory (see
[Dependencies](#dependencies)).

Load order is: global config, project config, global plugin directory, project plugin
directory. Every hook of every plugin runs in that order. Duplicate npm packages with the
same name and version load once.

## Plugin shapes

### Default export with an id (recommended)

```ts title=".novaway/plugin/release-helper.ts"
import type { Plugin } from "@novaway/plugin"

export default {
  id: "release-helper",
  server: (async ({ client, directory }) => {
    return {
      // hooks
    }
  }) satisfies Plugin,
}
```

`id` is required for path-based plugins, so NovaWay can report, deduplicate, and reload
them reliably.

### Named exports (short form)

```ts title=".novaway/plugin/release-helper.ts"
import type { Plugin } from "@novaway/plugin"

export const ReleaseHelper: Plugin = async ({ client, directory }) => {
  return {
    // hooks
  }
}
```

A module may export several functions this way and each is applied. Prefer the `default`
form for anything you intend to publish.

### Options

Any spec can carry an options object, passed to your plugin as the second argument:

```json title="novaway.json"
{
  "plugin": [["./plugin/audit.ts", { "endpoint": "https://audit.example.com" }]]
}
```

```ts title=".novaway/plugin/audit.ts"
export default {
  id: "audit",
  server: async (ctx, options) => {
    const endpoint = String(options?.endpoint ?? "")
    return {
      "session.idle": async () => {
        await fetch(endpoint, { method: "POST", body: JSON.stringify({ cwd: ctx.directory }) })
      },
    }
  },
}
```

## The plugin context

Your exported function receives one object:

| Field                    | Use it for                                                  |
| ------------------------ | ----------------------------------------------------------- |
| `client`                 | `@novaway/sdk` client for calling the running server        |
| `project`                | Project id and VCS information                              |
| `directory`              | Session working directory — prefer this over `process.cwd()` |
| `worktree`               | Repository root, for stable relative paths                  |
| `serverUrl`              | The local server this plugin runs against                   |
| `$`                      | Bun shell ([docs](https://bun.com/docs/runtime/shell))      |
| `experimental_workspace` | `register(type, adapter)` for remote workspace adapters     |

## Dependencies

Local plugins and custom tools can use external npm packages. Add a `package.json` to your
config directory with the dependencies you need.

```json title=".novaway/package.json"
{
  "dependencies": {
    "shescape": "^2.1.0"
  }
}
```

NovaWay runs `bun install` at startup to install these. Your plugins and tools can then
import them.

```ts title=".novaway/plugin/safe-shell.ts"
import { escape } from "shescape"

export const SafeShell = async () => {
  return {
    "tool.execute.before": async (input, output) => {
      if (input.tool === "bash") {
        output.args.command = escape(output.args.command)
      }
    },
  }
}
```

:::note
`@novaway/plugin` is not published to npm yet. Until it is, point at the copy in this
repository so the import resolves:

```json title=".novaway/package.json"
{
  "dependencies": {
    "@novaway/plugin": "file:../novaway-coder/packages/plugin"
  }
}
```

A plugin that only uses hooks needs no import at all — the type import is erased at runtime.
:::

## Hooks

Mutate the `output` object in place. Throwing from a `*.before` hook aborts that single
operation and the message is surfaced to the model.

### Conversation

| Hook                                  | Input                                                 | Output                                                             |
| ------------------------------------- | ----------------------------------------------------- | ------------------------------------------------------------------ |
| `chat.message`                        | `sessionID`, `agent`, `model`, `messageID`, `variant` | `message`, `parts`                                                 |
| `chat.params`                         | `sessionID`, `agent`, `model`, `provider`, `message`  | `temperature`, `topP`, `topK`, `maxOutputTokens`, `options`        |
| `chat.headers`                        | same as `chat.params`                                 | `headers`                                                          |
| `experimental.chat.system.transform`  | `sessionID`, `model`                                  | `system: string[]`                                                 |
| `experimental.chat.messages.transform` | —                                                    | `messages`                                                         |

### Tools

| Hook                  | Input                                     | Output                              |
| --------------------- | ----------------------------------------- | ----------------------------------- |
| `tool`                | —                                         | map of tool id to a `tool()` definition |
| `tool.definition`     | `toolID`                                  | `description`, `parameters`         |
| `tool.execute.before` | `tool`, `sessionID`, `callID`             | `args`                              |
| `tool.execute.after`  | `tool`, `sessionID`, `callID`, `args`     | `title`, `output`, `metadata`       |

### Commands and shell

| Hook                      | Input                                  | Output  |
| ------------------------- | -------------------------------------- | ------- |
| `command.execute.before`  | `command`, `sessionID`, `arguments`    | `parts` |
| `shell.env`               | `cwd`, `sessionID`, `callID`           | `env`   |

`shell.env` applies to shell tool calls and to terminals NovaWay opens, so it is the right
place to inject credentials or project variables.

### Session and compaction

| Hook                                    | Input                                                                          | Output                                |
| --------------------------------------- | ------------------------------------------------------------------------------ | ------------------------------------- |
| `experimental.session.compacting`       | `sessionID`                                                                    | `context: string[]`, `prompt?: string` |
| `experimental.compaction.autocontinue`  | `sessionID`, `agent`, `model`, `provider`, `message`, `overflow`               | `enabled: boolean`                    |
| `experimental.text.complete`            | `sessionID`, `messageID`, `partID`                                             | `text`                                |

### Provider and auth

| Hook       | Purpose                                                        |
| ---------- | -------------------------------------------------------------- |
| `auth`     | Add a `/connect` flow for a provider (API key or OAuth)         |
| `provider` | Supply or override the model list for a provider                |

### Lifecycle

| Hook     | Input              | Purpose                                                                                                        |
| -------- | ------------------ | -------------------------------------------------------------------------------------------------------------- |
| `event`  | `event`            | Every bus event: `session.idle`, `message.updated`, `file.edited`, `session.error`, `todo.updated`, and more    |
| `config` | `Config`           | The merged config, before startup finishes                                                                     |
| `hook`   | `event`, `payload` | Kernel lifecycle events such as `SessionStart`, `PreToolUse`, `Stop`, `SubagentStart`. Set `output.result.decision = "deny"` to block |

## Examples

Each example is a complete file. Save it under `.novaway/plugin/` and restart — no config

### Send notifications

Send notifications when certain events occur:

```ts title=".novaway/plugin/notify.ts"
import type { Plugin } from "@novaway/plugin"

export const Notify: Plugin = async ({ $ }) => {
  return {
    event: async ({ event }) => {
      if (event.type === "session.idle") {
        await $`osascript -e 'display notification "Session completed!" with title "NovaWay"'`
      }
    },
  }
}
```

We are using `osascript` to run AppleScript on macOS. On Linux call `notify-send`, on
Windows use a PowerShell toast script.

:::note
The NovaWay desktop app already sends system notifications when a response is ready or a
session errors, so a notification plugin is mostly useful for the CLI and TUI.
:::

### .env protection

Prevent NovaWay from reading `.env` files:

```ts title=".novaway/plugin/env-protection.ts"
import type { Plugin } from "@novaway/plugin"

export const EnvProtection: Plugin = async () => {
  return {
    "tool.execute.before": async (input, output) => {
      if (input.tool === "read" && String(output.args.filePath).includes(".env")) {
        throw new Error("Do not read .env files")
      }
    },
  }
}
```

### Inject environment variables

Inject environment variables into every shell execution, both tool calls and the terminals
NovaWay opens:

```ts title=".novaway/plugin/inject-env.ts"
import type { Plugin } from "@novaway/plugin"

export const InjectEnv: Plugin = async ({ directory }) => {
  return {
    "shell.env": async (input, output) => {
      output.env.PROJECT_ROOT = input.cwd || directory
      output.env.NOVAWAY_TRACE = "1"
    },
  }
}
```

### Custom tools

Plugins can add tools the model can call:

```ts title=".novaway/plugin/custom-tools.ts"
import { type Plugin, tool } from "@novaway/plugin"

export const CustomTools: Plugin = async () => {
  return {
    tool: {
      mytool: tool({
        description: "This is a custom tool",
        args: {
          foo: tool.schema.string().describe("Anything"),
        },
        async execute(args, context) {
          return { title: "mytool", output: `Hello ${args.foo} from ${context.directory}` }
        },
      }),
    },
  }
}
```

`tool()` takes three fields:

- `description`: what the tool does, shown to the model
- `args`: a [Zod](https://zod.dev) raw shape, available as `tool.schema`
- `execute`: called with the parsed args and a tool context

The tool context carries `sessionID`, `messageID`, `agent`, `directory`, `worktree`, an
`abort` signal, plus `metadata()` for live progress and `ask()` for permission prompts. See
[Custom tools](/docs/custom-tools) for the full API.

:::note
If a plugin tool uses the same name as a built-in tool, the plugin tool takes precedence.
:::

### Logging

Use `client.app.log()` instead of `console.log` for structured logging. `console.log`
output is swallowed by the TUI, while server logs land in
`~/.local/share/novaway/log`:

```ts title=".novaway/plugin/logging.ts"
import type { Plugin } from "@novaway/plugin"

export const Logging: Plugin = async ({ client }) => {
  return {
    event: async ({ event }) => {
      if (event.type !== "session.idle") return
      await client.app.log({
        body: {
          service: "logging",
          level: "info",
          message: "session idle",
          extra: { session: event.properties.sessionID },
        },
      })
    },
  }
}
```

Levels are `debug`, `info`, `warn`, `error`. See [SDK](/docs/sdk) for the client API.

### Compaction hooks

Customize the context included when a session is compacted:

```ts title=".novaway/plugin/compaction.ts"
import type { Plugin } from "@novaway/plugin"

export const Compaction: Plugin = async () => {
  return {
    "experimental.session.compacting": async (input, output) => {
      output.context.push(`
## Custom Context

Include any state that should persist across compaction:
- Current task status
- Important decisions made
- Files being actively worked on
`)
    },
  }
}
```

The `experimental.session.compacting` hook fires before the model generates a continuation
summary. Use it to inject domain-specific context that the default prompt would miss.

You can also replace the compaction prompt entirely by setting `output.prompt`:

```ts title=".novaway/plugin/custom-compaction.ts"
import type { Plugin } from "@novaway/plugin"

export const CustomCompaction: Plugin = async () => {
  return {
    "experimental.session.compacting": async (input, output) => {
      output.prompt = `
You are generating a continuation prompt for a multi-agent session.

Summarize:
1. The current task and its status
2. Which files are being modified and by whom
3. Any blockers or dependencies between agents
4. The next steps to complete the work

Format as a structured prompt that a new agent can use to resume work.
`
    },
  }
}
```

When `output.prompt` is set it replaces the default prompt completely and
`output.context` is ignored.

### Add a request header

Useful for gateway routing, tracing, or upstream analytics:

```ts title=".novaway/plugin/trace-headers.ts"
import type { Plugin } from "@novaway/plugin"

export const TraceHeaders: Plugin = async ({ project }) => {
  return {
    "chat.headers": async (input, output) => {
      output.headers["X-Session-Id"] = input.sessionID
      output.headers["X-Project"] = project.id
    },
  }
}
```

### Change model parameters per agent

```ts title=".novaway/plugin/tuning.ts"
import type { Plugin } from "@novaway/plugin"

export const Tuning: Plugin = async () => {
  return {
    "chat.params": async (input, output) => {
      if (input.agent !== "plan") return
      output.temperature = 0.2
      output.maxOutputTokens = 8000
    },
  }
}
```

### Extend the system prompt

```ts title=".novaway/plugin/house-style.ts"
import type { Plugin } from "@novaway/plugin"

export const HouseStyle: Plugin = async () => {
  return {
    "experimental.chat.system.transform": async (input, output) => {

```

### Deny an action from the kernel hook table

The `hook` hook receives every kernel lifecycle event, including the ones without a
dedicated named hook:

```ts title=".novaway/plugin/kernel-policy.ts"
import type { Plugin } from "@novaway/plugin"

export const KernelPolicy: Plugin = async () => {
  return {
    hook: async (input, output) => {
      if (input.event === "PreToolUse" && input.payload.tool === "write") {
        output.result.decision = "deny"
        output.result.reason = "writes are disabled in this workspace"
      }
    },
  }
}
```

## Providers and auth

The `auth` hook adds an entry to `/connect`:

```ts title=".novaway/plugin/my-gateway-auth.ts"
import type { Plugin } from "@novaway/plugin"

export const MyGatewayAuth: Plugin = async () => {
  return {
    auth: {
      provider: "my-gateway",
      methods: [
        {
          type: "api",
          label: "API key",
          prompts: [{ type: "text", key: "accountId", message: "Account id", placeholder: "acct_..." }],
        },
      ],
    },
  }
}
```

Use `type: "oauth"` with `method: "auto"` or `method: "code"` when you need a browser
round-trip. The built-in GitHub Copilot, GitLab, Codex, Cloudflare, Azure and DigitalOcean
integrations are all implemented this way.

The `provider` hook supplies the model list for a provider that already exists — define the
provider itself in `novaway.json` (or let a built-in plugin create it), then return its
models here. Each entry is a complete v2 `Model` record:

```ts title=".novaway/plugin/my-gateway-models.ts"
import type { Plugin } from "@novaway/plugin"
import type { Model } from "@novaway/sdk/v2"

export const MyGatewayModels: Plugin = async () => {
  return {
    provider: {
      id: "my-gateway",
      // each entry must be a complete Model record; usually you spread an existing one
      models: async () => ({
        "fast-1": { ...someExistingModel, id: "fast-1", name: "Fast 1" } as Model,
      }),
    },
  }
}
```

The hook also receives the provider and the stored auth, so you can fetch the list from the
upstream API instead of hardcoding it.

## Workspaces

`experimental_workspace.register(type, adapter)` teaches NovaWay how to create and tear
down remote workspaces. The adapter interface is exported from `@novaway/plugin` as
`WorkspaceAdapter`: `configure`, `create`, `remove`, and `target`.

## TUI plugins

Plugins that change the terminal interface export `tui` instead of `server`:

```ts title=".novaway/plugin/my-tui.ts"
import type { TuiPlugin } from "@novaway/plugin/tui"

export default {
  id: "my-tui",
  tui: (async (api) => ({
    // commands, dialogs, keymaps, slots, toast
  })) satisfies TuiPlugin,
}
```

A module exports either `server` or `tui`, never both. Commands, dialogs, prompts, slots,
keymaps and attention sounds are all on the `api` object; the type definitions in
`@novaway/plugin/tui` are the reference.

## Debugging

- `novaway debug info` lists the plugins NovaWay resolved after merging all config.
- `novaway plugin <module>` installs an npm plugin and writes the config entry.
- `--pure` disables every external plugin, which is the fastest way to confirm a plugin is
  the cause of a problem.
- Hook errors are logged with the plugin id. A throwing `tool.execute.before` aborts that
  single call, not the session.
