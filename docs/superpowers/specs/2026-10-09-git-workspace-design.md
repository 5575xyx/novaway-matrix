# Git 工作区设计（Lazygit 式）

日期：2026-10-09
状态：设计已定稿，待实施

## 背景与目标

现有 Git 能力散在两处：侧栏的 `Git` 页（约 50 列宽，点文件跳去主区 `git-diff` 标签页、点提交跳去 `commit-detail` 标签页），以及那两个标签页本身。窄栏装不下「边看 diff 边操作」，来回跳标签是主要摩擦。

目标：在主区新增一个 `Git` 标签页，做成 Lazygit 式的双栏工作区 —— 左列五个面板、右侧常驻差异视图、底部键位提示条，键盘优先走完日常流程。

## 决策记录

| 问题            | 结论                                                                                       |
| --------------- | ------------------------------------------------------------------------------------------ |
| 工作区放哪      | 主区标签页，完整 Lazygit 双栏（方案 B）                                                    |
| 侧栏原有 Git 页 | 瘦成入口 + 摘要，点它开工作区（方案 2）                                                    |
| 功能范围        | v1 = 日常循环（看 diff/暂存/提交/拉推/**撤销上次提交**）+ 分支/贮藏；之后再补全量          |
| 交互方式        | 键盘优先；鼠标（点文件看 diff）保留，悬停显形那套后续再做                                  |
| 界面语言        | 全中文；快捷键保留字母（`tab`/`j`/`k`/`空格`）；git 术语中文化（暂存/提交/拉取/推送/贮藏） |
| 标签名          | 主区与侧栏都保留 `Git`，不改成「版本控制」                                                 |
| 多仓库/多远程   | 只做多远程（选一个 remote 推送/拉取）；多仓库另开一轮                                      |

## 布局

```
┌ 侧栏 ──────┐ ┌ 聊天 │ Git ─────────────────────────┐
│ ● 主分支 ↑91 │ │ ┌ 状态 ────────── ┌ 差异 ─────────────┐ │
│ 6 个变更    │ │ │ ...（左列 36 列） │ ...（占满剩余）    │ │
│ 40f2c3c …   │ │ └───────────────── └──────────────────┘ │
│ ↳ 打开工作区 │ │ tab 切面板 j/k 选 空格 暂存 c 提交 ? 帮助 │
└─────────────┘ └─────────────────────────────────────────┘
```

- 左列固定 **36 列**，五个面板纵向堆叠。
- 差异面板占满剩余宽度。
- 终端总宽 70–79 列时左列收到 **30 列**；总宽 < 70 列时整个工作区显示「终端太窄，请加宽到 70 列以上」，不硬挤 —— 差异视图窄于 30 列就没法读了。

## 面板

顺序照 Lazygit：**状态 → 文件 → 分支 → 提交 → 贮藏**。现有侧栏的「同步」并入状态面板的 `p`/`f` 键，「远程」并入状态面板的「远程」行（见下）。

### 状态

四行可操作条目，`j/k` 选行，`空格` 作用于当前行。

| 行   | 内容                                      | `空格` 的动作                                                |
| ---- | ----------------------------------------- | ------------------------------------------------------------ |
| 分支 | 当前分支名 + 领先/落后（如 `主分支 ↑91`） | 跳到「分支」面板                                             |
| 远程 | 选中的远端名（如 `origin  gitee`）        | 切换远端（等同 `m`）                                         |
| 变更 | 文件数 + 加/删行数（如 `6 个 +120 -44`）  | 有未暂存改动时**全部暂存**；已无未暂存改动时**全部取消暂存** |
| 提示 | 一句话状态                                | 无                                                           |

「提示」行的文案：`工作区干净` / `有未提交改动` / `分支与远程 diverged` / `不是 git 仓库`。

选中「远程」行时，在该行下方摊开完整 URL（多占两行）。`f` 推送是不可逆动作，推错地方很痛，这里多花两行是值的。没有配置远端时该行显示 `未配置远端`，`空格` 进入添加远程的行内输入。

### 文件

- `j/k` 上下选文件；`空格` 暂存/取消暂存；`a` 全部暂存。
- 状态词用中文：`已改` / `新增` / `删除` / `重命名` / `未跟踪`，后面跟 `+N -M` 行数。
- `enter` 把焦点切到右侧差异视图（此时 `j/k` 变成滚动差异内容）。
- `d` 丢弃、`x` 删除未跟踪 —— 都要二次确认。
- `y` 复制文件路径 —— **前置条件**：`y` 依赖把文本写进系统剪贴板。实施前先确认 `packages/tui` 里有没有可用的剪贴板通道（终端程序通常要靠 OSC 52）。**没有的话，v1 就砍掉所有 `y`**，改在差异视图里靠终端原生的选中复制。别为了一个次要功能引入剪贴板依赖。

### 分支

- `j/k` 上下选分支；`空格` 切换到该分支；`n` 新建分支（下方开一行输入框）；`d` 删除（二次确认，当前分支不让删）。
- 本地与远程分支同列显示。远程分支保留 git 原本的 `origin/main` 这种「远端名/分支名」形式，不译成中文 —— 它是要喂给 `git push <remote>` 的真实引用。当前分支标 `●`。

### 提交

- `j/k` 上下选提交；`enter` 让右侧差异视图显示该提交改了什么；`y` 复制完整哈希（同上，依赖剪贴板）。
- 每行显示：短哈希 + 提交主题（截断到列宽）。
- `z` 撤销上次提交，即 `git reset --soft HEAD~1`（改动退回暂存区）。**这不是** Lazygit 那个著名的大 `z` —— 那是把「最近一次任意操作」整体回退的操作级撤销栈（unstage、discard、commit 都能撤），不在 v1。这里只是把现有侧栏的「撤销上次提交」原样搬过来，别混淆。

### 贮藏

- `j/k` 上下选贮藏；`空格` 弹出；`d` 丢弃（二次确认）。
- 空时显示 `（暂无）`。

### 差异（右侧面板）

内容跟着左列焦点行变：

| 焦点在哪    | 差异视图显示               |
| ----------- | -------------------------- |
| 文件        | 该文件工作区/暂存区的 diff |
| 提交        | 该提交的 diff              |
| 分支        | 该分支相对当前分支的 diff  |
| 状态 / 贮藏 | 保持上一次的内容（或空）   |

复用现有 `git-diff-view.tsx` 的 diff 渲染能力（见「文件结构」）。

## 键位

### 全局（工作区内任何时候）

| 键                  | 动作                                    |
| ------------------- | --------------------------------------- |
| `tab` / `shift-tab` | 下一 / 上一面板                         |
| `1`…`5`             | 直接跳到 状态/文件/分支/提交/贮藏       |
| `c`                 | 提交（有暂存内容时）                    |
| `p` / `f`           | 拉取 / 推送（走「远程」行选中的远端）   |
| `r`                 | 刷新                                    |
| `?`                 | 帮助（弹出一张键位表，见下）            |
| `esc`               | **左列焦点时**：关闭 Git 标签页，回聊天 |

### 局部（按焦点面板）

见上文各面板说明。底部键位提示条**跟着焦点面板变** —— 在文件面板里 `空格` 是暂存，在状态面板里 `空格` 作用于当前行。

### 差异视图获得焦点时

用户在文件/提交面板按 `enter` 后，焦点移到右侧差异视图，此时拦截器换成差异视图自己的键位：`j/k` 或 `↑/↓` 滚动、`pgup`/`pgdn` 翻页。`esc` **退回左列焦点**（不关闭标签页 —— `esc` 的含义随焦点变，这是上面「关闭标签页」那条的限定条件）。数字键 `1`–`5` 在此时不响应。

### `?` 帮助

弹出一张只读的键位表，内容就是本文「键位」一节的两张表（全局 + 当前面板），`esc` 关闭。不做分页、不做搜索。

## 危险操作：二次确认，不用弹窗

按 `d` 时那一行变成黄色的 `再按一次 d 确认`，再次按键才真执行，期间按任何其他键取消。覆盖：丢弃文件改动、删除未跟踪文件、删除分支、丢弃贮藏。

理由：键盘流不断，也不用维护 `DialogAlert`。

**超时用可注入的时钟**：确认态默认 3 秒后自动取消，但这个计时不直接读 `setTimeout`，而是走注入的时钟接口 —— 否则测试只能靠真实 sleep，既慢又不稳（参照 `packages/novaway/test/AGENTS.md` 里 TestClock 的用法约束）。

## 焦点与按键拦截

工作区获得焦点时注册一个前置键拦截器，吃掉 `j`/`k`/`tab`/`esc`/`?`/`c`/`p`/`f`/`a`/`d`/`x`/`y`/`n`/`m`/`r` 以及数字 `1`–`5`，不漏给聊天输入框。

**放行**：`ctrl+c`（中断）、`ctrl+l`（清屏）这类全局键。

差异视图获得焦点时（用户按 `enter` 进入滚动模式），拦截器换成差异视图自己的滚动键位；`esc` 退回左列焦点。

## 提交：行内输入，不是弹窗

按 `c` 后左列底部展开一行 `提交信息：▌`，`enter` 提交、`esc` 取消，内容过长自动换行。没有暂存内容时按 `c` 提示「没有可提交的暂存内容」。

**三处行内输入（提交信息、新建分支、添加远程）共用同一个行内输入组件**，不要各写一套：都是「在左列底部展开一行 → 接受按键 → enter 确认 / esc 取消」，差别只在标题和回调。

## 多远程

数据来自现有的 `git remote -v`（侧栏已拉，工作区复用 `parseGitRemotes`）。选中的远端存成工作区内的一个信号，默认 `origin`，没有 `origin` 时取第一个。

`p` 拉取 → `git pull <remote> <branch>`；`f` 推送 → `git push <remote> <branch>`。分支没有上游时，推送前询问是否 `--set-upstream`。

切换远端本身不执行任何 git 命令，只改选中状态；推送/拉取时才用它。

## 入口与打开方式

- 侧栏 `Git` 页：三行摘要（当前分支、变更数、最近一条提交）+ 一行 `↳ 打开工作区`。点击即开。
- 命令面板：在 `src/keymap.tsx` 注册一条 `namespace: "palette"` 的命令「打开 Git 工作区」（`command-palette.tsx` 从 keymap 取命令，有现成口）。
- 主区标签条上，工作区标签与 `聊天` 并列，**可关闭**（`聊天` 不可关）。

## 与既有功能的关系

| 既有功能                                       | 处理                                                                                 |
| ---------------------------------------------- | ------------------------------------------------------------------------------------ |
| 侧栏文件树点文件 → 开 `git-diff` 标签页        | **保留**。那是另一个上下文（看任意文件），与工作区无关。                             |
| 侧栏提交 → 开 `commit-detail` 标签页           | **保留**。工作区内看提交走右侧差异面板，不新开标签。                                 |
| 侧栏 Git 页的「同步 / 远程 / 历史 / 贮藏」区块 | **移除**，能力并入工作区。                                                           |
| 侧栏 Git 页的 `+ 添加远程`                     | **搬到**工作区状态面板的「远程」行。                                                 |
| 侧栏 Git 页的 `撤销上次提交`                   | **搬进**工作区提交面板（键 `z`），留在 v1 —— 侧栏已有这个功能，v1 删掉就是功能回退。 |

## 数据流

- 数据加载复用 `src/util/git-exec.ts` + `src/util/git-status.ts` 的 `parseGitBranches/Commit/Numstat/Remotes/StashList/Status`。
- **刷新时机**：打开工作区时、每次执行完一个 git 变更操作后、按 `r` 时。
- **不轮询**。TUI 里轮询 git 会拖慢，且会话进行中 agent 正在改文件时，靠 `r` 手动刷新即可。

## 错误处理

- git 命令失败：状态面板「提示」行显示原因，不弹窗。
- 不是 git 仓库：工作区整体显示 `不是 git 仓库`，面板仍渲染但全空。
- 没有 `cwd`：复用现有 `new Error("no cwd")` 的处理路径。

## 测试策略

沿用现有 `bun test` 模式（`testEffect` + `it.effect`/`it.live`）：

- **面板渲染**：各面板给定假数据能画出预期行（中文状态词、`+N -M`、领先/落后标记）。
- **键位映射**：`focus.ts` 的键位表是纯数据，可直接断言「焦点在文件面板时 `空格` → 暂存」。
- **二次确认**：按 `d` 进入确认态、超时内再按执行、期间按其他键取消、超时自动取消。走注入的时钟推时间，不写死 sleep。
- **剪贴板前置检查**：先验证 `packages/tui` 有没有可用的剪贴板通道（OSC 52 或别的）。**没有就砍掉所有 `y` 键**，并把设计里对应的段落删掉，别留着当假设。
- **多远程**：两个远端时切换选中项、`f`/`p` 拿到的是选中的那个。
- **焦点拦截**：工作区获得焦点时按键不漏给聊天输入框；`ctrl+c` 仍放行。
- **宽度预算**：70/79/80 列三种宽度下左列列数正确；< 70 列显示提示。

测试挂在 `test/component/git-workspace*.test.tsx`。注意现有 `test/component/prompt-card.test.tsx` 的 `renderCard` 说明：挂载组件需要 `KeymapProvider` 栈。

## 不在 v1 范围

按行/按 hunk 暂存、交互式 rebase、cherry-pick、bisect、Lazygit 那种**操作级撤销栈**（把最近一次任意操作整体回退，unstage/discard/commit 都能撤 —— 注意区别于 v1 里提交面板的 `z` 撤销上次提交）、worktree、多仓库切换、鼠标悬停显形。这些要跟 git 的补丁编辑和交互式命令打交道，或牵扯到会话上下文，单独开一轮。
